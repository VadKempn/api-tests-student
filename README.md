## Запуск тестов

1. Установите любое IDE для разработки: [Jetbrains GoLand](https://www.jetbrains.com/ru-ru/go/) (Платное или по студенческой лицензии), [VS Code](https://code.visualstudio.com/) (бесплатное).
2. Установите [Git](https://git-scm.com/install/) на компьютер
3. [Установите](https://go.dev/doc/install) Go версии 1.25.1
4. Создайте публичный fork [api-tests-student](https://github.com/qa-course-avito/api-tests-student).
5. Склонируйте свой fork через HTTPS: `git clone https://github.com/<ваш-логин>/api-tests-student.git`.
6. Подтяните необходимые зависимости через команду в корне проекта:

```bash
   go mod tidy
```

7. В файле `.env.override` (создайте его в корне, если нет) выставьте правильные значения для переменных окружения:

```
TEST_LOGIN=your_login
TEST_PASSWORD=your_password
TEST_OWNER_LOGIN=another_user_email
TEST_OWNER_PASSWORD=another_user_password
```

Для избранного нужны две разные учётные записи TestBoard. Зарегистрируйте их на сайте перед запуском: `TEST_LOGIN` добавляет объявления в избранное, `TEST_OWNER_LOGIN` создаёт объявления для этих проверок. Это нужно, потому что API запрещает добавлять собственные объявления в избранное. Для остальных тестов используется `TEST_LOGIN`.

`.env.override` исключён из Git. Не добавляйте в репозиторий реальные пароли и токены.

8. Для запуска всех тестов достаточно выполнить команду в корне проекта:

```bash
  go test -v ./...
```

9. Отдельный пакет с тестами можно запустить командой:

```bash
  go test -v ./tests/scenarios/myAdvertisement/
```

Для проверки повторяемости выполните полный запуск три раза подряд с отключённым кэшем:

```bash
go test -count=1 -v ./...
go test -count=1 -v ./...
go test -count=1 -v ./...
```

## Покрытие

- Создание объявления со всеми полями и тремя фотографиями: получение по id, поиск по полному названию, список фотографий и скачивание загруженных файлов.
- Ошибки обязательных полей, длины названия и описания, цены, количества и числа фотографий.
- Создание без токена и с неверным токеном.
- Полный цикл избранного, включая исчезновение записи после удаления объявления владельцем.
- Несуществующий и некорректный id, отсутствие авторизации, повторное добавление, собственное объявление и лимит в 50 записей.

Тесты используют уникальные названия и удаляют свои объявления и записи избранного через `t.Cleanup`, в том числе при падении проверки. Существующие данные аккаунтов не удаляются. В тесте лимита учитываются уже имеющиеся записи пользователя.

Перед запросами к учебному API установлена пауза 300 мс, чтобы не отправлять их слишком частыми сериями.

Адреса получения и удаления объявления используются по актуальному Swagger: `GET /advertisement?id=...` и `DELETE /advertisement?id=...`. Для фотографий используется `GET /advertisements/{id}/photos`.

Ошибки `500` намеренно не вызываются: они требуют сбоя сервера или базы данных. Воспроизводимые ответы `400`, `401`, `403`, `404` и `409` покрыты тестами.

## Логирование

Для включения логирования request/response в консоль: выставьте переменную окружения `DEBUG=true` в
`.env.override`

## Запуск линтера

2. Запуск линтера (из корня репозитория):

```bash
  golangci-lint run
```
